- **Framer Motion `whileInView` does NOT reliably fire for elements ALREADY in viewport on initial mount under Next 16 + React 19 + framer-motion 12.** This is a documented bug class affecting `<SectionHeader as="h1">` heroes and `<FadeIn>` components above-fold. Symptom: page renders blank above-the-fold; visitor lands → sees empty space → bounces within 0-3 seconds. Below-fold SectionHeader (h2, h3) keeps whileInView since IntersectionObserver fires reliably when scrolling element INTO view (the bug only affects already-in-view-on-mount). Trade-off: site-wide loss of 0.5s fade-in animation. Acceptable because invisible-hero was actively destroying conversion. <!-- added 2026-05-06 hero render fix -->
- **JSX attribute strings DO process JS unicode escapes** at compile time — `title="Privé Studio"` should render as "Privé Studio". BUT a literal-character `\` followed by `u00e9` in source (6 separate chars: backslash, u, 0, 0, e, 9) renders LITERALLY as "Privé". Avoid mixing escape forms; prefer the actual char `é` over `é` in JSX attribute values. Browser-tab metadata title (JS object) processes the escape correctly so the bug is asymmetric — tab shows "Privé", h1 shows literal escape — easy to miss. <!-- added 2026-05-06, lesson: visual audits beat text-only audits for typography -->
